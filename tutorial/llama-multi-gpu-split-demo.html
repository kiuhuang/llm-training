llama.cpp multi-GPU · layer / tensor / row split on 4×GPUs — animated inference

Set with -sm. layer (default) = pipeline parallelism: each GPU holds contiguous layers, the token travels GPU0→1→2→3. tensor (experimental, 2026) = real tensor parallelism: every layer sharded across all GPUs — weights and KV cache — via a "meta device" abstraction, with cross-GPU all-reduces per layer. row is the deprecated legacy TP path (dense weights cut by rows, partials summed) — kept here only for comparison. -ts a,b,c,d sizes the split in layer/row; tensor shards evenly.

■ Layer split — -sm layer default

      
    
        
  • Pipeline parallelism. Each GPU receives a contiguous block of layers, sized by -ts ratios (e.g. 32 layers, -ts 3,2,1,1 → 13/9/5/5).
    • 
        
  • For every token, the activation flows GPU0 → GPU1 → GPU2 → GPU3; one GPU computes while the others wait.
    • 
        
  • KV-cache stays local: each GPU stores K/V only for its own layers. VRAM use ∝ layers owned — heterogeneous cards are fine.
    • 
        
  • Prompt prefill can pipeline ubatches (micro-batches) across GPUs — that's why the prefill Gantt overlaps when the checkbox is on.
    • 
        
  • + minimal interconnect traffic (one small activation hop per boundary) · tolerant of slow links (even RPC/multi-machine) · most mature path.
        − single-stream utilization ≈ 1/N; the GPU owning the most layers sets the latency; idle cards during decode.
    • 
      

    

    

      
▦ Tensor split — -sm tensor experimental

      
    
        
  • True tensor parallelism via a "meta device" abstraction (backend-agnostic TP work led by JohannesGaessler, merged 2026). Every weight tensor is sharded across all participating GPUs.
    • 
        
  • Per layer, attention heads and FFN neurons are split evenly (-ts not used — exclude GPUs with --device instead).
    • 
        
  • Two cross-GPU reductions per layer — after the attention output-projection and after the FFN down-projection — implemented as ring all-reduces: every GPU ends each reduction holding the full activation, no re-broadcast step.
    • 
        
  • KV cache is sharded too (each GPU keeps its heads' K/V) → balanced memory and more context headroom vs. a single card.
    • 
        
  • Needs -fa on; -fit unsupported (set -c manually); backend sampling currently falls back to CPU; best performance on multiple NVIDIA GPUs (CUDA).
    • 
        
  • + all GPUs busy every layer · minimizes token latency · generation scales best.
        − interconnect-hungry: reductions per layer, and their messages grow with batch (prefill gains need fast links).
    • 
      

    

    

      
▤ Row split — -sm row deprecated

      
    
        
  • Status per official docs: deprecated — "avoid in new deployments." Superseded by -sm tensor, "which should be universally superior if it can be used."
    • 
        
  • How it worked: only the dense weights were split, by rows — each matmul produced partial outputs that had to be summed across GPUs (one reduction per matmul, summed on one card, then re-broadcast onward).
    • 
        
  • It was the original multi-GPU approach (2023); layer split replaced it as default in late 2023 because the hand-off cost per token was far lower. It also never worked everywhere — e.g. on Vulkan it silently fell back to layer split.
    • 
        
  • Kept in this demo as the historical ancestor of tensor parallelism — and to feel how reduction frequency dominates multi-GPU decode latency.
    • 
      

    

    

      
Which one when — cheat sheet

      
    
        
  • Model doesn't fit one GPU (the common case): -sm layer + -ts matched to VRAM. Done.
    • 
        
  • Fastest token generation / lowest latency on NVLinked (or fat-PCIe, fast-interconnect) NVIDIA cards: try -sm tensor -fa on — expect the best decode speed, experimental rough edges.
    • 
        
  • Max serving throughput for many users: layer split + continuous batching pipelines ubatches across GPUs; true TP engines (vLLM, TensorRT-LLM) compete at datacenter scale.
    • 
        
  • Old tutorials / scripts with -sm row: they still run, but switch them to tensor (or drop the flag for the layer default).
    • 
      

    

  


  

    Real-world notes (per llama.cpp docs/multi-gpu.md, 2026). Flags: -sm / --split-mode none|layer|tensor (plus deprecated row) · -ts / --tensor-split a,b,c,d — normalized proportions for layer/row (newer builds also accept sizes like 24G,10G,0,0); tensor shards segments evenly · -ngl accepts auto|all|N · -mg main GPU for none · -dev/--list-devices to pick/exclude devices · -fa required for tensor · -fit auto-fit (unsupported with tensor — set -c yourself). History: row split was the original approach; layer split became the default in late 2023; backend-agnostic tensor parallelism ("meta device") landed experimentally in 2026. Known tensor-mode quirk: "backend sampling not supported with SPLIT_MODE_TENSOR; using CPU" (llama-context.cpp). If a GPU can't hold its layer share in layer mode, llama.cpp shifts layers or spills to CPU — this demo just flags the overflow. Timings are illustrative, not benchmarks.
    Shortcuts: space run/pause · s step · r reset.
